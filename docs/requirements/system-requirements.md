# System Requirements

## Purpose

This document captures the initial requirements that will drive the architecture of the project.

Architecture decisions should always be based on requirements rather than technology preferences.

---

## Functional Requirements

Functional requirements describe what the system must do.

Examples:

- Users can create deliveries.
- Drivers can update delivery status.
- Customers can track deliveries.

---

## Non-Functional Requirements

Non-functional requirements describe how the system should behave.

Examples:

- High availability
- Security
- Scalability
- Performance
- Reliability
- Auditability

---

## Key Takeaway

Before designing an architecture, it is essential to understand:

- Business requirements
- Functional requirements
- Non-functional requirements
- Constraints
- Architectural drivers
